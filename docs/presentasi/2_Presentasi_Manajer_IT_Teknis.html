Domain Logic: Inventory Integrity

Integritas Stok & Pola Buku Besar (Ledger)

Invarian BR-01: Total = Tersedia + Dipinjam + Rusak / Perbaikan
Jalur Tunggal BukuBesarStok
  • Kolom stok pada tabel items dilarang keras di-update langsung oleh Controller atau Seeder.
  • Setiap perubahan stok wajib memanggil BukuBesarStok dalam transaksi database atomik.
Tabel Mutasi Append-Only
  • Tabel stock_movements (11 enum jenis mutasi) tidak mendukung operasi UPDATE atau DELETE.
  • Status peminjaman tidak disimpan statis di kolom, selalu diturunkan dinamis oleh StatusPeminjaman.
Concurrency & Resilience

Kontrol Konkurensi & Anti-Deadlock

Pessimistic Locking

Memakai lockForUpdate() pada baris transaksi dan barang untuk mencegah race-condition saat sisa stok diperebutkan di detik yang sama.

Urutan Kunci Deterministik

Urutan penguncian selalu: tabel transaksi terlebih dahulu (loans/klaim), lalu baris items diurutkan menaik (ORDER BY id ASC) untuk mencegah circular deadlock.

Kunci Idempotensi (UUID)

Setiap POST kiosk wajib menyertakan UUID idempotency_key. Replay request dengan kunci identik mengembalikan respon 200 OK tanpa menduplikasi potongan stok.

Otomasi Retry Deadlock

Operasi mutasi multi-baris dibungkus dalam DB::transaction(..., 3) untuk otomatis melakukan retry hingga 3 kali jika terjadi benturan transaksi di MySQL.

Code Organization

Pola Desain: Isolasi Aturan Bisnis

Skinny Controllers

Controller murni orkestrasi: menerima Form Request yang tervalidasi, memanggil Service domain, dan mengembalikan API Resource yang terformat seragam.

Rich Domain Services

Semua aturan bisnis BR-01..34 terisolasi murni di app/Services/. Frontend Vue tidak pernah menghitung kelayakan status atau stok.

Database CHECK & FK

Seluruh relasi menggunakan ON DELETE RESTRICT. Dilengkapi CHECK constraints pada rentang tanggal, enum valid, dan kuota untuk mencegah data anomali.

Security & Compliance

Postur Keamanan & Perlindungan PII

Zero Hardcoded Credentials

Tidak ada password bawaan di Git, seeder, maupun bundle produksi. Akun admin dibuat dan direset secara interaktif via artisan CLI dengan Bcrypt.

Isolasi PII (Nomor Telepon)

Nomor kontak peminjam hanya dapat dibaca oleh staf berizin di panel admin. Respon kiosk publik disaring ketat dari data kontak peminjam.

Rate Limiting Bertingkat

Login admin dibatasi 5 percobaan gagal per 15 menit. Lookup kode Kiosk memiliki mekanisme penguncian IP bertahap via PembatasKodeKiosk.

Audit Trail Append-Only

Tabel audit_logs merekam seluruh aktivitas otentikasi, perubahan stok, dan ekspor dokumen secara permanen tanpa pernah menyimpan password.

Quality Assurance

Strategi Pengujian Otomatis (Automated Testing)

480+ Tests Hijau (Pest & PHPUnit)

Mencakup validasi Form Request, perizinan Sanctum, boundary kiosk, dan skenario happy/unhappy path untuk seluruh rute API.

Uji Konkurensi Riil

Bukan mock atau tiruan. Pengujian konkurensi dijalankan menggunakan 2 koneksi database MySQL terpisah untuk menguji efektivitas lockForUpdate().

Uji Stres Acak (Fuzzing)

Simulasi 1.000 operasi transaksi acak berurutan dengan seed tetap untuk menguji daya tahan buku besar stok terhadap crash data.

Pemeriksaan Invarian Otomatis

Helper assertInvarian() dipanggil otomatis di setiap akhir tes Service untuk memastikan rumus stok selalu seimbang 100%.

Database Hardening

Manajemen Hak Akses Database (Least Privilege)

User MySQL Hak Akses (Privileges) Fungsi Operasional
migrator ALL PRIVILEGES / Hak DDL Penuh Khusus eksekusi php artisan migrate saat rilis
app_inventaris SELECT, INSERT, UPDATE (Tanpa DDL, DELETE hanya sessions/cache) Operasional harian backend aplikasi
backup SELECT, SHOW VIEW, TRIGGER, LOCK TABLES Cron job mysqldump berkala

Mitigasi Dampak Keamanan: Jika terjadi eksploitasi logika aplikasi, akun app_inventaris secara native ditolak MySQL untuk melakukan DROP TABLE atau merusak struktur database.
